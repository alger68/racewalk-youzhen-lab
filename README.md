## 2.10.0：通用版與實用功能整合

- 網站標題、頁首、圖示文字及新紀錄預設改為通用名稱；既有使用者紀錄中的姓名不批次覆寫。
- 新影片自動以獨立解碼器觀測播放幀率，以穩定的相鄰影格間隔中位數估計。跳過暖機與丟失回呼；不足或不穩定時顯示無法確認。這不是原始拍攝 fps 的保證，也不會自動認定慢放倍率；套用需確認倍率，並清除時間已確認狀態。
- MediaPipe、人物偵測、RTMPose、ReID 模型使用固定 SHA-256 快取；每次讀取重新驗證，損壞則重新下載。儲存不可用時回退網路；不快取使用者影片或報告。WASM 保留既有載入方式。
- 自動診斷列出身分缺值、左右膝可用格數、時間及地面設定缺漏，可跳至相關影格。這些是資料品質說明，不是違規判決。
- 沿用現有雙模型核對與持續追蹤；未移植另一版本的自動地面估計、離地濾波或裁判偵測機率，避免未驗證的數值混入結果。
- 新 GitHub 儲存庫維持原有名稱，網址不因移除介面姓名而改變。

## 2.8.1：人物候選自動去重

- 每支影片自動以頭肩、軀幹與尺度核對不同裁切的重複候選；同一次辨識中分開出現的候選不合併，避免把相鄰人物合成一人。
- 待確認區域再做一次局部骨架辨識。骨架候選與待確認區域分開編號；候選數不等於實際選手人數，工作人員也可能被偵測。
- 只將選定框交給原有身分追蹤；未改動接觸、角度守門，也不補算遮擋角度。
- 134 項核心測試通過；另以 IMG_3289.mov 的 8 個畫面執行原生模型比對，詳見 [人物候選驗證](docs/person-discovery.md)。

## 2.8：局部複核與原始觀測恢復

- 區分「複核點不足」與「模型位置衝突」。前者才以預先固定的較緊全身裁切重辨識一次；保留原本與重試中觀察到的衝突，不選最接近的答案。
- 恢復時先等待下一個清楚且穩定的觀測，再保留前一格實際觀察到的點位。遮擋格、身分缺口、最後尚未確認的單格均保留缺值。
- 左右資料品質顯示局部複核／相鄰確認找回的格數；缺值原因可直接跳回影格。人工修改會清理被取代的複核紀錄，並撤回依賴被修改影格的自動恢復值。
- 128 項核心測試通過。IMG_3289.mov 全段重新推論 624 格：左側三點可用 135 → 163，右側 414 → 469；這是可用性比較，不是準確率或犯規判定。詳見 [恢復方法與原片驗證](docs/observation-recovery.md)。

## 2.7：接觸時序與量測誤差

- 接觸候選加入像素垂直距離、人體相對尺度、觀測法向速度與 HMM 前後幀核對；單格清楚的高於地面觀測仍保留。
- 灰色區段列出缺失設定或點位原因，左右腳各有格數與跳轉複查。固定鏡頭／整段地面有效性需使用者確認；追拍不自動假裝已校準。
- 可選 1€ 平滑趨勢疊加原始曲線。原始骨架、角度與窗口最低值不變，缺口不連線。
- 可選 Monte Carlo 膝角敏感度（1,024 次）：σ 預設 2 px 僅是假設，中央 95% 模擬範圍尚未校準、不進入裁判或訓練判讀。
- 新設定可儲存／匯入，報告與匯出保留假設。120 項核心測試通過；624 格原片辨識資料的後處理重播保持原始點位與缺值。
- 沒有量化準確率改善或實機測試結論。詳見 [數學方法與驗證](docs/measurement-methods.md)。

## 使用順序

1. 新增一支無痛 Easy 側面原片，建議 10–15 秒、1080p，100 MB 以下。
2. 填選手、鏡位、近鏡頭側、行進方向、症狀及實測配速。首次症狀預設「尚未確認」。
3. 核對原始拍攝 fps、檔案慢放倍率及分析起訖；不清楚時間映射就不勾確認。
4. 新影片自動偵測人物，點選候選框／編號，或手動圈選一位選手，再開始追蹤分析。可在暫停畫面按「偵測畫面所有人物」重掃。框隨目標移動；短暫遮擋時繼續掃描，待連續核對同一人後自動恢復量測。改選另一人仍另建片段。
5. 自動分析建立骨架與待確認事件，完成或中止時嘗試儲存。錯誤會保留畫面並提示匯出 JSON。
6. 點候選事件回看鞋底，修正事件時間並確認 IC／Vertical／TO。未確認事件不進入正式窗口摘要。
7. 可用單幀辨識、人工髖膝踝三點、伸膝參考軸及 PNG 匯出和教練討論。
8. Judge View 隱藏骨架並依已確認倍率還原正常速度，人工填寫接觸與左右伸膝觀察。
9. 儲存複查、匯出 HTML／CSV／完整 JSON，或列印為 PDF。PNG 快照可加入當次 HTML／列印報告，但快照本身不儲存至歷史報告。
10. 要跨裝置重看原片，另按「備份原片」。否則只儲存點位及報告，下次需選相同 SHA256 的原檔。

## 科學與操作邊界

- 自動輸出是訓練篩查候選，不是競走違規判決。正常速度肉眼觀察不由慢動作角度／毫秒轉換。
- 170° 虛線與低於 170° 的窗口計數是尚未校準的工程複查提示。165° 亦非官方門檻，本版不以其自動判紅。
- 二維膝角評估只使用側面近鏡頭腿，遠側可顯示明確標記的參考值，低信心、遮擋、人物過小顯示缺值。正後面髖連線傾角不是三維骨盆旋轉或臨床診斷。
- 足部關鍵點與固定地面線無法準確代表鞋底接觸。地面參考需同一平面，鞋底清楚且仍須逐幀複查。
- 本版不自動輸出總分、官方犯規率、公分步幅、3D 髖旋轉、病因診斷或個人化復健課表。需專家標註及實拍校準後擴充。
- 步頻需要確認的連續左右交替 IC 和時間映射。離地間隔另需事件對齊有解碼時間的影格；使用取樣間隔而非標稱 240fps 計算不確定範圍。
- 影片時間步進是瀏覽器 seek，不保證恰好一個原始編碼幀。可使用「下一個分析幀」跳至已保存影格；VFR、補幀、快門模糊、影片鏡像需要人工處理。
- 模型可能對競走交叉／遮擋失敗。本版結合逐幀全景、圈選區放大及周圍多人體偵測，加上位置、軀幹尺寸與衣著色彩連續性追蹤圈選目標；不依模型陣列順序接人。能確認同一軀幹時，腿部跳點或局部遮擋只暫停該側量測；人物身分歧義、軀幹重疊、位置／衣著不連續時暫停取值，整段影片仍持續掃描；只在通過連續身分核對後恢復。長時間消失或相似衣著人物交錯後，無足夠證據便保持缺值。門檻為未經實拍校準的工程保護，不保證身份辨識正確率。
- 跨週比較請維持同選手、鏡位、實測配速與有效窗口數；歷史表可看角度摘要，不能以角度越大就推論越好。

## 技術結構

- React／TypeScript／vinext、隨專案提供的 shadcn UI 元件。
- `lib/vision.ts`／`lib/vision.worker.ts`：背景模型運算、影片解碼取樣；同來源模型與 WASM 靜態資產，不依賴外部 CDN。

- `drizzle/`：資料庫建立遷移；已發布遷移不可改寫。
- `tests/core.test.cjs`：量測、未知值、事件確認、時間誤差、資料驗證和匯出防注入。

## 目標追蹤資料相容性

- 每個新片段保存圈選時間、目標識別碼與逐幀追蹤狀態；伺服器拒絕其他目標、搜尋中仍有點位、未確認身分與跨缺口共用量測區間；舊版永久中斷規則保留供舊紀錄驗證。
- 初始圈選框只標記起點，後續顯示目前目標骨架的移動框。搜尋框明確區分最後確認位置與待核對候選，不輸出預測角度。
- 「追蹤至此幀」從原圈選點逐幀重新關聯，保留整段搜尋缺值；已有分析或人工複查時，保存原紀錄並另存本次結果，不把不同次的追蹤鏈混接。
- 舊版 JSON 可讀取並明確標示未鎖定目標，須載入原片重選分析；舊資料不會被宣稱已修正。
- 僅使用影格內的衣著顏色摘要；在記憶體中比對，不儲存臉部或身份嵌入。


## 起始辨識修正

- 起始未取得骨架時，圈選框顯示「尚未鎖定」，不再宣稱為最後可靠位置。報告、HTML／CSV 與 PNG 同步區分起始失敗及取得目標後的追蹤中斷。
- `lib/pose-region.ts` 將圈選／周圍辨識的點位還原至原片座標；後續區域依上一個可靠目標框移動。全景及周圍的競爭選手仍參與遮擋與身分歧義檢查。
- 同一人體在不同範圍的重複結果只做核對，不拼接骨架。腿部結果不一致就停用該側量測；原始點位仍用於人物交錯檢查，不能藉停用數值掩蓋遮擋。
- 無偵測、身體品質不足、圈選外偵測及多個目標有不同提示。姓名為使用者填寫的紀錄，不是模型辨識出的真實姓名。
- 使用本次截圖的影片區域、相同 Lite 模型與 0.6 信心設定，在 Python CPU 重現：全景 0 組、圈選區 1 組、周圍 2 組骨架。帶入追蹤邏輯後可取得圈選軀幹；兩側腿部因跨範圍點位分歧暫停取值。這是單張截圖的診斷，尚不能代表原始影片的連續追蹤成功率或瀏覽器 GPU 結果。
- 36 項測試涵蓋座標還原、未鎖定狀態、重複偵測、同一人移動、其他人入框、腿部交錯及資料隔離；未更動正式判讀門檻。
