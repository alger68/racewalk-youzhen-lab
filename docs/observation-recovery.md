# 局部複核與原始觀測恢復（2.8）

這次處理「複核點不足」和「等待恢復首格」造成的可避免缺值。沒有降低原本關節可見度、跨模型位置、身分或遮擋門檻；沒有加入推測的關節座標。既有 2.7 接觸、平滑及誤差模擬方法保持不變。

## 局部重辨識

1. 原 MediaPipe Full 骨架先由 RTMPose-s 在原 bbox × 1.25、3:4 比例的全身區域複核。
2. 記錄原本有座標但不一致的 `conflicts`，與 RTMPose 沒有足夠觀測的 `unobserved`。模型輸出分數不是校準後機率。
3. 只有頭、左右肩已通過複核、原模型髖膝踝均可見、該腿沒有已觀察位置衝突、但至少一個腿部複核點不足時，才固定用 bbox × 1.05 再辨識一次。上限一次；所有符合條件的候選包含旁人均走相同規則。
4. 第二次仍需以相同解剖標籤對上原骨架的頭肩。不同頭肩使身分量測暫停，左右標籤衝突使兩側暫停。缺頭肩不能確認新腿部點位。
5. 只接受原本缺少複核證據、重試後與原 MediaPipe 點位吻合的關節。新發現的位置衝突保留；不同裁切只融合「是否支持原始點位」的證據，從不平均、交換或替換座標。
6. 新資料照常通過旁人關節碰撞、軀幹身分、腿形、時間連續性及恢復檢查。完整影片持續掃描。

若原模型自己沒有看到腿部，或原片遮住了腳，以上流程不提供缺少的座標。緊裁切也不會創造原影像沒有的解析度。膝角可用不代表鞋底可見，鞋底仍逐點判斷。

## 相鄰觀測確認

既有兩格恢復檢查會把第一格永遠丟掉，即使後續已確認該格的實際點位。新版暫存第一個通過檢查的原始觀測，第二個清楚觀測到來後才接受它。

- 兩格必須是相鄰已解碼影格、時間遞增、實際時間差 ≤ 0.2 秒、同一 target ID、同一 continuity、皆為 locked，且無人工修改或影格不對齊。
- 兩格髖、膝、踝都須保留跨模型複核證據；相對軀幹的點位移動及腿節形狀須通過既有檢查。
- 只恢復原本理由為「等待連續兩格穩定」的立即前一格，不向前搜尋其他缺口。
- 恢復內容是前一格保存在記憶體的原始座標；不使用下一格座標、線性插值、平滑結果或步態週期推算。
- 被複核拒絕的腳跟／腳尖依然不可用，不因膝角恢復就給腳接觸判定。
- 紀錄 `recovered[side].confirmedAt`，儲存與匯入核對確認幀存在且同身分。取消、片尾的單一返回點與未完成的確認不會被接受。
- 人工標記取代相應關節的模型證據；若修改了確認依據的關節，撤回前一格該側的自動恢復，讓它重新進入人工複核。其他腿與身分資料保持原狀。
